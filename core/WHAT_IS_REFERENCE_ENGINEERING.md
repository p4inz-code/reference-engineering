# What Is Reference Engineering?

**Reference Engineering** is the systematic practice of identifying, gathering,
analyzing, and organizing reference material before and during production —
with the explicit goal of answering specific technical and creative questions,
not merely collecting visual inspiration.

---

## The One-Sentence Distinction

A reference *collector* asks: *"What looks like what I want to make?"*

A reference *engineer* asks: *"What specific questions does my production need answered — and what reference answers each one?"*

---

## Why "Engineering"?

Engineering implies:

- **Intent** — you know what you are building before you build it
- **Specification** — the inputs are defined, the outputs are measured
- **Process** — the same method produces reliable results across different practitioners
- **Failure analysis** — when it goes wrong, you can identify why and fix it

Reference gathering, done correctly, has all four. The word "engineering"
is not a metaphor. It is a description of how systematic pre-production
reference work actually functions when done at a professional level.

---

## What Reference Engineering Is Not

**Not moodboarding.** A mood board communicates aesthetic direction to other
people. Reference Engineering answers production questions for yourself.
These overlap but are not the same thing.

**Not inspiration collecting.** Pinterest boards and image folders are inputs
to Reference Engineering, not the practice itself. The practice is the
analysis that extracts usable production information from those inputs.

**Not just 3D art.** Reference Engineering originated in a 3D art context
(see `MANIFESTO.md`) but applies to any discipline with a pre-production phase.
Every discipline section in this library applies the same methodology to
different production questions.

**Not a one-time task.** Reference Engineering includes updating and auditing
reference as production reveals what pre-production missed. The brief you write
on day one is a version, not a final document.

---

## The Core Loop

```
DEFINE questions  →  IDENTIFY reference types  →  GATHER targeted material
       ↑                                                      ↓
   AUDIT gaps    ←   ANALYZE and extract rules   ←   ORGANIZE by question
       ↑                                                      ↓
   UPDATE brief  ←←←←←←←←← production reveals new questions ←←←←←←←←←
```

This loop runs at every major production milestone, not once at the start.

---

## The Seven Principles

The complete principles are defined in `MANIFESTO.md`. Summary:

| # | Principle | Core Idea |
|---|---|---|
| 1 | Reference answers questions | Every piece of reference should answer a specific production question |
| 2 | The gap is most important | What's missing hurts more than what's present |
| 3 | Stages need different reference | Silhouette, material, and detail reference are not the same thing |
| 4 | Reference has a hierarchy | Real thing > analog > extracted principle |
| 5 | Style is extractable rules | Shape language, density, material behavior — write them down |
| 6 | Reference is versioned | Revisit at every milestone, not just at the start |
| 7 | Discipline transfers | The methodology works across all fields with pre-production phases |

## The Reference Pyramid

The Reference Pyramid defines the seven layers of reference that every
production needs. See `REFERENCE_PYRAMID.md` for the full breakdown.

In short: silhouette and proportion at the foundation, hero detail at the peak.
Most reference boards have too much at the peak and nothing at the foundation.

## Who Needs Reference Engineering?

**Any practitioner who has experienced:**
- Mid-production stalls because a key production question was unanswered
- Deliverables that missed the brief because the brief was unclear
- Reference boards that looked complete but didn't prevent problems
- Rework caused by discovering (too late) how something was supposed to behave

**By field:** 3D artists, VFX artists, game designers and developers,
web developers, app developers, UI/UX designers, concept artists, architects,
filmmakers, sound designers, music producers, security researchers.

See `disciplines/` for field-specific guides.
